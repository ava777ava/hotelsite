API «Флигеля»

Версия 1. Данные — JSON в кодировке UTF-8. Даты — ГГГГ-ММ-ДД. Деньги — числа в рублях. Ключи создаёт владелец аккаунта в приложении: «Интеграции».

Доступ

Каждый запрос подписывается ключом в заголовке Authorization: Bearer flg_…. Ключ показывается один раз при создании — сохраните его; потерянный ключ отзывается и создаётся заново. Права ключа: read — только чтение, write — ещё создание и изменение броней и цен. Лимит — 120 запросов в минуту на ключ; сверх лимита ответ 429.

curl https://ВАШ-ДОМЕН/api/v1/properties \
  -H "Authorization: Bearer flg_xxxxxxxxxxxx"

Ключ работает только с данными своего аккаунта. В демо-версии ключи не работают.

Объекты, номера, категории

GET /api/v1/properties

Список объектов: id, name, address, phone, check_in_time, check_out_time.

GET /api/v1/rooms?property_id=…

Номера: id, name, property_id, room_type_id, room_type, capacity, base_price. Параметр property_id необязателен.

GET /api/v1/room-types

Категории номеров: id, property_id, name, capacity, base_price, min_stay.

Брони

GET /api/v1/bookings?from=2026-07-01&to=2026-08-01

Брони, пересекающиеся с периодом [from, to), не более 1000. Период обязателен, не длиннее 400 дней. Необязательные фильтры: property_id, status (confirmed, pending, cancelled). Закрытия дат (blocked) не отдаются.

GET /api/v1/bookings/{id}

Одна бронь. Поля: id, property_id, room_id, check_in, check_out, status, source, guest_name, guest_phone, guest_email, guests_count, total_price, paid_amount, notes, created_at, updated_at.

POST /api/v1/bookings — нужен ключ write
curl -X POST https://ВАШ-ДОМЕН/api/v1/bookings \
  -H "Authorization: Bearer flg_xxxxxxxxxxxx" -H "Content-Type: application/json" \
  -d '{"room_id": "…", "check_in": "2026-07-10", "check_out": "2026-07-13",
       "guest_name": "Анна Петрова", "guest_phone": "+7 900 000-00-00", "guests_count": 2}'

Обязательно: room_id, check_in, check_out. Необязательно: guest_name, guest_phone, guest_email, guests_count, total_price (если не указана — считается по ценам и тарифам), paid_amount, notes, status (confirmed по умолчанию или pending). Источник брони всегда other. Если номер на эти даты занят, ответ 409, "code": "overlap" — двойную бронь система не допускает ни при каких условиях.

PATCH /api/v1/bookings/{id} — нужен ключ write

Меняет даты, номер, данные гостя, стоимость, статус. Чтобы отменить бронь, передайте "status": "cancelled". Удаления нет — отменённые брони остаются в истории. Чтобы не затереть правки сотрудника, передайте expected_updated_at (значение updated_at из последнего чтения): при расхождении ответ 409, "code": "stale".

Цены

GET /api/v1/prices?room_type_id=…&from=2026-07-01&to=2026-07-15

Цена, минимальный срок и признак закрытия продаж на каждую ночь периода [from, to) (до 400 дней): date, price, min_stay, closed. Если на дату цена не задана, отдаётся базовая цена категории.

PUT /api/v1/prices — нужен ключ write
{"room_type_id": "…", "date_from": "2026-07-10", "date_to": "2026-07-12", "price": 4500}

Задаёт цену, min_stay и/или closed (true — закрыть продажи) на даты от date_from до date_to включительно; можно ограничить weekdays (0 — понедельник … 6 — воскресенье). Через iCal цены на площадки не передаются — это ограничение самих календарей.

Вебхуки

Вместо постоянных запросов «что нового» подпишитесь на события. В приложении, «Интеграции → Вебхуки», укажите адрес (только https, публичный сервер) и события:

СобытиеКогда
booking.createdпоявилась новая бронь — из приложения, с сайта, из API или из календаря площадки
booking.updatedизменились даты, номер, данные гостя, стоимость, оплата или статус
booking.cancelledбронь отменена
booking.testпроверка вебхука кнопкой «Проверить»

Закрытия дат событий не создают. На адрес приходит POST с JSON:

{"event": "booking.created", "id": "<номер доставки>",
 "data": {"id": "…", "property_id": "…", "room_id": "…", "check_in": "2026-07-10", "check_out": "2026-07-13",
          "status": "confirmed", "source": "avito", "guest_name": "…", "guest_phone": "…", "guest_email": "…",
          "guests_count": 2, "total_price": 10500, "paid_amount": 0, "notes": "", "created_at": "…", "updated_at": "…"}}

Заголовки: X-Fligel-Event, X-Fligel-Delivery (повтор той же доставки приходит с тем же номером — обрабатывайте идемпотентно) и X-Fligel-Signature: sha256=… — HMAC-SHA256 от тела запроса в точности как оно пришло с секретом вебхука (whsec_…, виден в приложении). Проверяйте подпись и сравнивайте через constant-time функцию.

# Python
import hmac, hashlib
def valid(secret: str, raw_body: bytes, header: str) -> bool:
    expected = "sha256=" + hmac.new(secret.encode(), raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, header)

// Node.js
const crypto = require('crypto');
const valid = (secret, rawBody, header) => {
  const expected = 'sha256=' + crypto.createHmac('sha256', secret).update(rawBody).digest('hex');
  return header.length === expected.length && crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(header));
};

Ответьте кодом 2xx в течение 8 секунд. Иначе доставка повторяется с растущей паузой (2, 4, 8… минут, не дольше часа), всего 8 попыток; потом помечается недоставленной (видно в приложении). Перенаправления (3xx) не выполняются. Адреса во внутренние сети отклоняются.

Ошибки

Ответ с ошибкой — JSON {"error": "понятный текст по-русски"}, иногда с полем field или code.

КодЗначение
401нет ключа, он неверный или отозван
403у ключа нет права записи; аккаунт приостановлен
404объект не найден (или принадлежит другому аккаунту)
409номер занят на эти даты (overlap) или бронь изменили до вас (stale)
422неверные данные в запросе
429превышен лимит запросов
