# Как выложить «Флигель» на сервер — пошаговая инструкция

Инструкция для тех, кто раньше не разворачивал серверы. Все команды — копипаста,
выполняются по очереди. Занимает примерно 30–40 минут.

## Что понадобится

1. **VPS (виртуальный сервер)** с Ubuntu 24.04, минимум 2 ГБ RAM, 20 ГБ диска.
   Подойдёт любой провайдер с серверами в РФ (по 152-ФЗ данные должны храниться в России) —
   например, Selectel, Timeweb Cloud, VK Cloud, Yandex Cloud.
2. **Домен** (например, `booking.вашдомен.ru`) — купить у любого регистратора
   (reg.ru, timeweb и т.п.). Можно и без домена, но тогда не будет HTTPS.
3. Доступ к серверу по SSH (провайдер присылает IP, логин `root` и пароль или SSH-ключ
   сразу после заказа сервера).

## Шаг 1. Настройте домен

В панели управления доменом добавьте A-запись, указывающую на IP вашего сервера:

```
Тип: A
Имя: booking (или @, если домен только для этого сайта)
Значение: <IP вашего сервера>
```

DNS обновляется от нескольких минут до нескольких часов. Проверить можно так:

```bash
ping booking.ваш-домен.ru
```

Если видите IP вашего сервера — можно двигаться дальше. Если сертификат (шаг 4)
не выпустится сразу — это, скорее всего, DNS ещё не обновился, скрипт скажет,
как повторить попытку позже.

## Шаг 2. Подключитесь к серверу

С компьютера (Windows — через PuTTY или Windows Terminal, Mac/Linux — обычный терминал):

```bash
ssh root@<IP вашего сервера>
```

Введите пароль, который прислал провайдер (или он подключится по ключу автоматически).

## Шаг 3. Скачайте проект

```bash
apt-get update -y && apt-get install -y git
cd /opt
git clone <URL вашего репозитория> fligel
cd fligel/fligel
```

Замените `<URL вашего репозитория>` на адрес вашего git-репозитория
(например, `https://github.com/ваш-логин/hotelsite.git` — тогда после клонирования
зайдите в `hotelsite/fligel`, путь может отличаться в зависимости от структуры репозитория).

## Шаг 4. Запустите установочный скрипт

```bash
chmod +x deploy/setup.sh
sudo ./deploy/setup.sh booking.ваш-домен.ru you@example.ru
```

Второй аргумент — ваш email, на него certbot пришлёт уведомление, если сертификат
скоро истечёт (обычно продлевается автоматически, но на всякий случай).

Скрипт сам:
- поставит Docker, nginx, certbot, ufw;
- откроет в файрволе только порты 22 (SSH), 80 (HTTP), 443 (HTTPS) — остальное закрыто;
- создаст `.env` со сгенерированным `SECRET_KEY` и паролем базы данных;
- настроит nginx на ваш домен;
- соберёт и запустит приложение в Docker;
- подождёт, пока сайт откликнется;
- выпустит бесплатный HTTPS-сертификат (Let's Encrypt);
- поставит ежедневный бэкап базы данных в 03:00 ночи (хранится последних 14 копий).

Если что-то пошло не так на шаге сертификата — не страшно, сайт уже работает по HTTP,
повторите позже вручную:

```bash
certbot --nginx -d booking.ваш-домен.ru
```

## Шаг 5. Откройте сайт

Перейдите в браузере на `https://booking.ваш-домен.ru/app/` — должна открыться
страница входа/регистрации. Зарегистрируйте первый аккаунт — вы станете владельцем
(роль `owner`).

Публичная страница бронирования для гостей будет на `https://booking.ваш-домен.ru/book/<slug>`
(slug объекта задаётся в настройках после регистрации).

## Проверка, что всё работает

```bash
curl https://booking.ваш-домен.ru/health
```

Должно вернуть `{"ok": true, ...}`. Если `ok: false` — смотрите логи:

```bash
docker compose logs -f app
```

## Бэкапы

- Автоматический бэкап уже настроен (каждую ночь в 03:00, хранится последних 14 копий,
  файлы лежат в `backups/` внутри папки проекта).
- Сделать бэкап вручную прямо сейчас:
  ```bash
  ./deploy/backup.sh
  ```
- Восстановить базу из бэкапа (⚠️ полностью заменяет текущие данные):
  ```bash
  ./deploy/restore.sh backups/fligel_2026-01-01_03-00-00.sql.gz
  ```
  Скрипт попросит подтвердить действие, набрав «да».
- Список доступных бэкапов:
  ```bash
  ls -lh backups/
  ```

Рекомендуется периодически скачивать бэкапы на свой компьютер или в облачное хранилище —
если сгорит сам сервер, копии в `backups/` на нём же не спасут.

## Логи

```bash
docker compose logs -f app     # логи приложения (Ctrl+C — выйти)
docker compose logs -f db      # логи базы данных
cat /var/log/fligel-backup.log # журнал бэкапов
```

Логи контейнеров автоматически ротируются (не более 10 МБ × 5 файлов на контейнер),
диск не переполнится.

## Обновление на новую версию

Когда в репозитории появятся новые изменения:

```bash
cd /opt/fligel/fligel
git pull
docker compose up -d --build
```

Данные в базе не пострадают — том с базой (`pgdata`) не пересоздаётся.

## Если что-то сломалось

1. `docker compose ps` — какие контейнеры запущены.
2. `docker compose logs app` — ошибки приложения.
3. `curl https://ваш-домен/health` — что именно не в порядке (база или планировщик).
4. В крайнем случае — восстановление из последнего бэкапа (см. выше).

## Полезно знать

- Все данные хранятся на сервере в России (том Docker `pgdata`), никакие внешние
  CDN/аналитика/зарубежный хостинг не используются — это требование 152-ФЗ.
- Telegram-уведомления, восстановление пароля по email и другие внешние интеграции
  по умолчанию выключены и включаются переменными в `.env` (см. `.env.example`) —
  без них ничего никуда не отправляется.
- `SECRET_KEY` в `.env` — секрет, не публикуйте его и не коммитьте `.env` в git
  (он уже в `.gitignore`).
