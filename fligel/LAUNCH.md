# Чек-лист запуска «Флигеля» перед первыми клиентами

Идите сверху вниз и ставьте галочки (`- [x]`). Пункты со знаком ⚠ — без них запускаться нельзя.
Подробные команды — в `deploy/DEPLOY.md`; здесь — что и в каком порядке сделать человеку.

Условные обозначения: **сервер** — команды на VPS из папки `/opt/fligel/fligel`.

---

## 1. Сервер и домен

- [ ] ⚠ Заказан VPS **в России** (Ubuntu 24.04, от 2 ГБ RAM, от 20 ГБ диска) — данные граждан РФ должны храниться на серверах в РФ (152-ФЗ, ч. 5 ст. 18).
- [ ] ⚠ Куплен домен и добавлена A-запись на IP сервера; `ping ваш-домен` показывает этот IP (шаг 1 в `deploy/DEPLOY.md`).
- [ ] Доступ по SSH-ключу, вход по паролю отключён (рекомендуется).
- [ ] ⚠ Выполнен `deploy/setup.sh ваш-домен ваш@email` — сайт открывается по **https**, сертификат выпущен.
- [ ] `curl https://ваш-домен/health` отвечает `{"ok": true, …}`.

## 2. Настройки `.env`

Файл `.env` в папке проекта на сервере (скрипт создаёт его сам; в git его не кладём). После правок: `docker compose up -d`.

- [ ] ⚠ `SECRET_KEY` — длинная случайная строка (скрипт генерирует сам; не короче 24 символов, иначе приложение не запустится).
- [ ] ⚠ `PUBLIC_BASE_URL=https://ваш-домен` (по нему строятся ссылки в письмах и календарях).
- [ ] `APP_TIMEZONE` — ваш часовой пояс (по умолчанию `Europe/Moscow`).
- [ ] ⚠ Реквизиты продавца для счетов: `SELLER_NAME`, `SELLER_INN`, `SELLER_KPP`, `SELLER_OGRN`, `SELLER_ADDRESS`, `SELLER_BANK`, `SELLER_BIK`, `SELLER_ACCOUNT`, `SELLER_CORR_ACCOUNT`, `SELLER_PHONE`, `SELLER_EMAIL`, `SELLER_SIGNER`.
- [ ] ⚠ `SELLER_VAT_NOTE` — строка про НДС/УСН на счёте (например «Без НДС»). **Система её не угадывает — уточните у бухгалтера.**
- [ ] Цены тарифов `PRICE_START`, `PRICE_BUSINESS`, `PRICE_PRO` (₽/мес) — совпадают с тем, что вы обещаете клиентам (лендинг и счета берут их отсюда).
- [ ] `DEMO_ENABLED=1` — если хотите кнопку «Посмотреть демо». Один раз: `docker compose exec app python -m app.demo`.
- [ ] Перезапуск, затем `curl https://ваш-домен/health`: `warnings` равно **0** (если больше — откройте `/operator/`: там тексты предупреждений, разберите каждое).

## 3. Почта (SMTP)

- [ ] ⚠ Заведён ящик для рассылки (Яндекс 360, Mail.ru для бизнеса, почта хостинга), в `.env`: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_USE_TLS`, `SMTP_FROM`.
- [ ] Проверка: на странице входа «Забыли пароль?» → письмо пришло, ссылка работает. Без SMTP восстановление пароля не работает.
- [ ] Письмо не попало в «Спам» (в DNS домена настроены SPF и DKIM — подскажет почтовый провайдер).

## 4. Оператор (вы) и первые аккаунты

- [ ] ⚠ Создан оператор: `docker compose exec app python -m app.admin create-operator you@mail.ru` — пароль показывается один раз, **запишите**.
- [ ] Вход в `https://ваш-домен/operator/` работает, в панели нет жёлтых предупреждений о настройках.
- [ ] Зарегистрирован **тестовый** клиент (как новый пользователь) и пройден путь: мастер объекта → бронь → страница `/book/<slug>` → заявка → подтверждение.
- [ ] Выставлен тестовый счёт из «Тариф и счета», он открывается и печатается, реквизиты верны; в панели оператора счёт отмечен оплаченным и продлил тариф.
- [ ] Тестовый клиент удалён (Настройки → удалить аккаунт) или переименован.

## 5. Резервные копии

- [ ] ⚠ Ночной бэкап работает: `ls -lh backups/` — есть свежий файл (ставится `setup.sh`, 03:00).
- [ ] ⚠ Проверка восстановления: `./deploy/verify_backup.sh` вручную → `curl …/health` показывает `backup_check.ok: true`. (Дальше она запускается сама по воскресеньям в 04:00.)
- [ ] Копии регулярно скачиваются **за пределы сервера** (на свой компьютер или в облако в РФ) — если сгорит сервер, копии на нём не помогут.
- [ ] Один раз проведена репетиция восстановления на чистом сервере/тестовой базе (`./deploy/restore.sh …`).

## 6. Мониторинг

- [ ] ⚠ Внешний монитор (UptimeRobot или аналог) на `https://ваш-домен/health`: тревога при коде ответа ≠ 200 **и** при тексте `"stale": true` / `"ok": false` в поле `backup_check`.
- [ ] Уведомления монитора приходят вам (почта/Telegram) — проверено тестовым отключением.
- [ ] Диск: `df -h` — достаточно места; раз в месяц проверять рост папки `backups/`.

## 7. Telegram и MAX (по желанию, но рекомендуется Telegram)

- [ ] Создан бот у `@BotFather`, токен записан в `TELEGRAM_BOT_TOKEN`.
- [ ] ⚠ Задан `TELEGRAM_WEBHOOK_SECRET` (случайная строка) — **без него вебхук можно подделать** (панель оператора и `/health` предупредят).
- [ ] Выполнен `setWebhook` со `secret_token` (команда в `deploy/DEPLOY.md`), в приложении «Уведомления» → «Подключить Telegram» → бот ответил.
- [ ] Придумано, **что именно** уходит в Telegram: в уведомлениях бывают имена гостей и даты. Telegram — зарубежный сервис; **уточните у юриста**, нужно ли об этом предупреждать гостей/клиентов и как это отражено в политике (раздел 10 «Передача данных третьим лицам» в `/legal/privacy`).
- [ ] MAX: бот создаётся только от верифицированного юрлица/ИП. Если подходит — `MAX_BOT_TOKEN`, `MAX_BOT_USERNAME`, `MAX_WEBHOOK_SECRET`; адаптер написан по документации и **не проверялся на живом токене** — проверьте отправкой тестового события.

## 8. Проверка синхронизации с площадками на ОДНОМ номере

Не подключайте сразу все номера: сначала один тестовый, чтобы увидеть реальные форматы Авито/Яндекса.

- [ ] **Включён режим отладки** («Площадки → Состояние синхронизации» → переключатель внизу; по умолчанию выключен — в календарях бывают имена гостей) — до подключения календаря, иначе первый обмен не сохранится.
- [ ] Выбран один реальный номер (лучше с отключённой публикацией или с тестовыми датами в далёком будущем).
- [ ] «Площадки» → нужная площадка → в строке номера вставлена ссылка календаря **с площадки**, нажато «Подключить» — статус «ок» (если ошибка — текст ошибки покажет, что не так).
- [ ] Нашу ссылку («Копировать») вставили **на площадке** в поле импорта календаря.
- [ ] «Площадки → Состояние синхронизации»: через 1–3 часа в колонке «Площадка забрала наш» появилось время и название бота (User-Agent). Если «ещё ни разу» или больше 6 часов — придёт предупреждение; проверьте настройку на площадке.
- [ ] Тест туда: создана тестовая бронь в шахматке → через час-два на площадке эти даты закрыты.
- [ ] Тест обратно: на площадке создана/закрыта тестовая дата → в течение 15 минут (или «Обновить всё») она появилась в шахматке.
- [ ] Тест отмены: бронь на площадке отменена → в шахматке стала «Отменена».
- [ ] «Эхо»: после обмена в состоянии нет лишних конфликтов; счётчик «эхо отброшено» растёт, а «Конфликты» пусты.
- [ ] **Сохранены сырые календари** (Площадки → Состояние → «Сырые календари», только владелец): скачайте `.ics` от каждой площадки и **добавьте как образцы в `tests/test_sync_formats.py`** — в тестах пока только форматы по стандарту RFC 5545 (открытых образцов Авито/Яндекса найти не удалось).
- [ ] Если формат площадки не разобрался («не разобран» в списке календарей) — не подключайте остальные номера, пришлите `.ics` разработчику.
- [ ] Только после этого подключены остальные номера и площадки. Для Яндекс Путешествий календарь подключается к **категории**, а не к номеру (переключатель «На площадке у вас»).
- [ ] Режим отладки оставлен включённым на первый месяц, потом выключен (при выключении сохранённое удаляется).

## 9. Юридические документы

Тексты в `/legal/privacy`, `/legal/pdn-consent`, `/legal/terms` — **черновики**, помечены на страницах.

- [ ] ⚠ Юрист проверил и доработал: политику обработки персональных данных, согласие на обработку, пользовательское соглашение/оферту; в них указаны **ваши** наименование, ИНН/ОГРН, адрес, email для обращений.
- [ ] Определены роли: для данных **гостей** гостиницы-клиента оператором ПД является сама гостиница, а вы — лицо, обрабатывающее данные **по её поручению** (ст. 6 ч. 3 152-ФЗ). Нужен договор/оферта с условиями поручения (цели, перечень действий, меры защиты, ответственность).
- [ ] Для данных **самих клиентов** (владельцы, сотрудники) оператор — вы.
- [ ] Паспортные данные гостей сервис **не собирает и не хранит** (только имя, телефон, email, пожелания) — убедитесь, что это так же написано в документах и объяснено клиентам (гостиницам): паспорт они оформляют для миграционного учёта своими средствами.
- [ ] Внутренние документы оператора ПД: приказ о назначении ответственного, перечень мер защиты, порядок реагирования на запросы субъектов и на утечки (уведомление РКН об инциденте — 24 ч/72 ч), журнал доступа.
- [ ] Реквизиты в футере лендинга и в оферте совпадают с реквизитами в счетах.

## 10. Роскомнадзор: уведомление об обработке персональных данных

- [ ] ⚠ **До начала обработки** (до приёма первых клиентов) подано уведомление об обработке ПД в Роскомнадзор (ч. 1 ст. 22 152-ФЗ) — через портал `pd.rkn.gov.ru` с учётной записью организации/ИП через Госуслуги. Если вы уже зарегистрированы как оператор по другой деятельности — подайте **изменения** (новые цели: «предоставление сервиса бронирования»).
- [ ] В уведомлении указаны: цели обработки; категории данных (ФИО, телефон, email, даты проживания, пожелания; **без** паспортных данных и специальных категорий); категории субъектов (клиенты-владельцы, их сотрудники, гости); способы (автоматизированная, с передачей по сети); **место размещения баз данных — Россия** (адрес ЦОД провайдера); меры защиты (шифрование HTTPS, разграничение доступа, резервные копии, журналирование); сведения о трансграничной передаче (если используете Telegram/почту за рубежом — укажите или откажитесь).
- [ ] Номер записи в реестре операторов сохранён и указан в политике обработки ПД.
- [ ] Если используете зарубежные сервисы для данных граждан РФ (Telegram, зарубежная почта) — проверена необходимость отдельного уведомления о трансграничной передаче (ч. 3 ст. 12 152-ФЗ) и локализации. **Решение — за юристом.**

## 11. Первые клиенты

- [ ] Подготовлена короткая инструкция «как начать» для клиента (ссылка на `/app/`, раздел «Справка» в приложении).
- [ ] Определён канал поддержки (email/телефон/мессенджер) и написан на лендинге и в счетах.
- [ ] Договорённость о том, как принимается оплата: счёт → оплата → вы вручную отмечаете в `/operator/` (автоматической оплаты пока нет).
- [ ] Пробный период 14 дней, напоминания об окончании идут письмами (нужен SMTP — п. 3).
- [ ] Первому клиенту проведён «первый день»: вместе заведены номера, цены, подключён один календарь (п. 8), включены только нужные модули (Настройки → Модули).

## 12. Перед запуском — последняя проверка

- [ ] `curl https://ваш-домен/health` → `ok: true`, `warnings: 0`, `backup_check.ok: true`.
- [ ] Прогнаны тесты на актуальной версии: `TEST_DATABASE_URL=… python -m unittest discover -s tests`, `eslint --config tests/eslint.config.mjs app/static/admin`.
- [ ] На телефоне открыты и пройдены: вход, «Сегодня», шахматка, создание брони, страница `/book/<slug>` (RU и EN).
- [ ] Версия записана (git-тег), известен порядок отката: `./deploy/restore.sh` + предыдущая версия образа.
