# Флигель: управление бронированиями

Сервис для посуточной аренды и небольших гостиниц. В одной шахматке собраны брони с Авито, Яндекс Путешествий, Суточно.ру, Островка и с вашего сайта. Календари площадок синхронизируются через iCal, а занять номер дважды не даст сама база данных.

Рабочее название «Флигель» меняется в `app/static/admin/index.html`, `app/static/admin/app.js` и на странице бронирования.

## Что уже работает

| Раздел | Что умеет |
|---|---|
| **Несколько объектов у одного владельца** | Переключатель объекта в боковом меню (и в мобильной шапке) — выбор запоминается. Добавить объект можно прямо в «Настройках». Шахматка, Цены, Площадки работают по выбранному объекту; на «Сегодня», «Броних» и «Отчётах» есть ещё и режим «Все объекты» |
| **Шахматка** | Номера по категориям, цены и число свободных номеров на каждый день, брони цветом по источнику. Протяните мышью по свободным клеткам, чтобы создать бронь. Существующую бронь можно перетащить в другой номер и/или на другие даты, а за край полоски — растянуть или сжать. На телефоне достаточно коснуться клетки |
| **Защита от овербукинга** | Пересекающиеся брони одного номера запрещены правилом в самой PostgreSQL (`EXCLUDE`-ограничение) — действует и при обычном создании брони, и при переносе перетаскиванием. Проверено тестом, где шесть гостей одновременно бронируют последний номер: проходит только один |
| **Карточка брони** | Гость, телефон, даты, номер, статус (подтверждена / ждёт оплаты / даты закрыты), сумма считается автоматически по ценам, есть учёт оплаты. Кнопка «История гостя по телефону» показывает все прошлые проживания по всем объектам и отмечает постоянных гостей (от 2 визитов) |
| **Поиск гостя** | Иконка поиска в шапке — ищет бронь по имени, телефону или email сразу по всем объектам и переносит на нужную дату в шахматке |
| **Перенос брони** | Брони перетаскиваются мышью (в другой номер и/или на другие даты), на телефоне — долгим нажатием и перетаскиванием. После этого открывается окно подтверждения: видно «было / станет», номер и даты можно поправить, цена пересчитывается по тарифам (или остаётся прежней, или вводится вручную). Пока не нажато «Подтвердить», ничего не сохраняется |
| **Быстрый старт и «Сегодня»** | На шахматке нового аккаунта — чек-лист настройки (номера, цены, площадки, сотрудники…). «Сегодня»: заезды, выезды, проживающие, свободно на ночь, сколько ещё должны гости |
| **Уведомления в Telegram** | Новая бронь, отмена, двойное бронирование, ошибка синхронизации, утренний дайджест. Каждый сотрудник подключает свой чат и выбирает события. Выключено, пока в `.env` нет токена бота |
| **Безопасность входа** | Блокировка на 15 минут после 5 неверных паролей, восстановление пароля по ссылке (1 час), смена пароля в профиле, заголовки безопасности и CSP |
| **Телефон** | Нижнее меню с разделом «Ещё», таблицы превращаются в карточки, окна открываются снизу, поля ввода не вызывают приближение на iPhone; сайт можно «установить» на экран телефона (PWA) |
| **Площадки (iCal)** | Для каждого номера или категории: наша ссылка для площадки и поле для ссылки площадки. Загрузка каждые 15 минут, ручное обновление, журнал ошибок |
| **Конфликты** | Если площадка продала даты, которые у вас уже заняты, система не затирает бронь, а показывает предупреждение в шахматке и в разделе «Площадки» |
| **Цены** | Базовая цена категории. Изменение сразу на период с выбором дней недели (например, выходные дороже), минимальный срок проживания, закрытие продаж. Закрытые даты уходят на площадки как занятые |
| **Сегодня** | Заезды, выезды и кто проживает на выбранный день, сколько осталось доплатить. Кнопка «Печать» готовит лист «Заезды и выезды на день» для администратора или горничной |
| **Брони** | Поиск по имени и телефону, фильтры по периоду, объекту и статусу |
| **Расходы** | Категории расходов (10 стандартных заводятся сами), быстрое добавление за 3 клика, повторяющиеся расходы (аренда, зарплата — создаются автоматически в свой день месяца), расход можно привязать к объекту, номеру или оставить общим на весь аккаунт, фильтры, итоги по категориям, выгрузка в CSV |
| **Отчёты** | Полноценная финансовая аналитика: выручка, расходы, прибыль, рентабельность, загрузка, ADR, RevPAR, средний срок проживания, доля отмен, долг гостей — со сравнением с прошлым периодом и тем же периодом год назад. Графики по месяцам, по дням недели и по структуре расходов. Разбивки по объектам, категориям и отдельным номерам, по источникам броней (с учётом комиссии площадки) и по категориям расходов. Выгрузка в CSV |
| **Бронирование на сайте** | Страница `/book/<адрес>`: гость выбирает даты, видит цену и отправляет заявку, система сама подбирает свободный номер. Для сайта есть код вставки (iframe) |
| **Заявки с сайта** | Новые заявки видны бейджем в меню и обновляются сами; подтверждаются или отклоняются одной кнопкой. Неподтверждённая заявка снимается через `REQUEST_TTL_HOURS` (по умолчанию 48 ч). Владельцу и администраторам приходит письмо и сообщение в Telegram. Форма защищена от спама (лимит по IP, ограничение заявок с одного телефона, скрытое поле-ловушка) |
| **Фото номеров** | До 8 фото на категорию (загрузка в «Настройках», сжатие в браузере, проверка типа файла на сервере); гости видят их на странице бронирования с просмотром во весь экран |
| **Импорт из CSV** | «Брони» → «Импорт»: переезд из Excel или другой системы. Сначала проверка (ничего не сохраняется), потом загрузка; пересечения и ошибки в строках показываются списком |
| **Справка** | Раздел «Справка» в приложении — краткие инструкции по ролям |
| **Управление сервисом** | Команда `python -m app.admin` (список аккаунтов, тариф, приостановка, сброс пароля, сводка); лимиты объектов по тарифам; журнал изменений каждой брони |
| **Деньги в брони** | История платежей и возвратов (способ, дата, кто принял), услуги из справочника, скидка с причиной, залог (не входит в выручку), печатный счёт; «касса» за период |
| **Тарифы и цены** | Тарифы категории (± % и ± ₽ за ночь: невозвратный, с завтраком), доплата за гостей сверх включённых, скидка за 7+/28+ ночей, календарь цен на 3 месяца с массовым редактированием, праздники РФ в календаре |
| **Гости** | Раздел «Гости» по телефону: визиты, суммы, теги, заметки, день рождения, чёрный список с предупреждением; шаблоны сообщений ({имя}, {даты}, {сумма к оплате}…) — на email, в Telegram, копирование для MAX; кнопки «позвонить / Telegram / MAX» |
| **Уборка** | Статусы номеров (чистый / нужна уборка / убирают / проверка / ремонт), экран горничной на телефоне, назначение, заметки к номерам, сообщение о поломке; контакты и суммы гостей горничной не отдаются |
| **Шахматка+** | Масштаб 2 недели / месяц / 3 месяца, фильтр категорий, заметки на даты, групповая бронь на несколько номеров, переселение посреди проживания, тёмная тема, горячие клавиши, отмена переноса и отмены брони |
| **Собственники** | Роль «Собственник» (только чтение своих объектов без контактов гостей) и месячный отчёт собственнику: выручка → комиссии площадок → расходы → комиссия УК → к выплате (CSV, печать) |
| **Уведомления** | Единый слой: колокольчик в интерфейсе + Telegram + MAX (оба выключены без токенов), у каждого сотрудника свой выбор каналов и событий; журнал действий владельца |
| **Без связи** | Офлайн-режим: последние экраны открываются только для чтения с пометкой, форма не теряется при обрыве связи и истёкшей сессии, защита от правок «в двух вкладках» |
| **Сотрудники** | Владелец, администратор (брони, цены, площадки, расходы) и горничная (только шахматка и заезды) |
| **Несколько клиентов** | Все данные разделены по аккаунтам (`account_id` в каждой таблице). Регистрация и мастер первого запуска уже есть, чужие данные недоступны (есть тесты) |

## Как устроено

- **Бэкенд:** Python 3.11+, Starlette и uvicorn, PostgreSQL 14+.
- **Фронтенд:** чистый JavaScript без сборки. Его отдаёт тот же сервер.
- **Фоновая синхронизация** работает внутри приложения, очередь задач хранится в PostgreSQL (`FOR UPDATE SKIP LOCKED`). Redis не нужен. Можно запускать несколько экземпляров: один календарь не обработают дважды.
- **152-ФЗ:** всё работает на одном сервере без внешних сервисов, шрифтов и CDN, поэтому данные остаются в России.

## Запуск на своём компьютере через Docker (проще всего, в том числе на Windows)

Нужен только Docker Desktop (на Windows ему нужен WSL2: в PowerShell от администратора `wsl --install`,
перезагрузка, затем установка Docker Desktop). Python и PostgreSQL ставить не нужно.

```bash
git clone -b feature/next https://github.com/ava777ava/hotelsite.git
cd hotelsite/fligel
cp .env.example .env        # на Windows cmd: copy .env.example .env
# в .env впишите:  SECRET_KEY=dev-secret-change-me   и   POSTGRES_PASSWORD=localtest123
docker compose up -d --build
docker compose exec app python -m app.demo      # демо-данные (по желанию)
```

Откройте http://localhost:8000/app/ (вход `demo@fligel.ru` / `demo12345`). Обновление до новой версии:
`git pull` и `docker compose up -d --build` — данные в базе сохраняются. Остановить: `docker compose down`.

## Запуск на своём компьютере без Docker

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
createdb fligel                      # нужна установленная PostgreSQL
cp .env.example .env                 # укажите DATABASE_URL, PUBLIC_BASE_URL=http://localhost:8000
python -m app.demo                   # демо-гостиница на 12 номеров (по желанию)
uvicorn app.main:app --reload
```

Откройте http://localhost:8000. Демо-вход: `demo@fligel.ru` / `demo12345`. Страница бронирования для гостей: http://localhost:8000/book/demo

В демо-данных — два объекта («Гостиница «Флигель»» и «Квартиры на сутки»), брони почти за 13 месяцев (для отчётов за год) и расходы за 12 месяцев с одним повторяющимся (аренда офиса).

Тесты: `TEST_DATABASE_URL=postgresql://postgres@127.0.0.1/fligel_test python -m unittest discover -s tests -v`

Проверить производительность на большом объёме данных: `python -m app.demo_load` — отдельный аккаунт `loadtest@fligel.ru` / `loadtest12345`, 70 номеров и 2 года броней и расходов (около 11 тысяч броней). Шахматка, отчёты и список броней должны открываться меньше чем за секунду — если на реальных данных это не так, в первую очередь проверьте индексы в `migrations/004_perf_indexes.sql`.

## Установка на сервер (Timeweb Cloud, Selectel, Yandex Cloud)

Подойдёт самый простой VPS: 1–2 ядра, 2 ГБ памяти, Ubuntu 24.04. Нужен домен, например `booking.вашдомен.ru`, с A-записью на IP сервера.

**Вариант с Docker** (проще всего):

```bash
apt update && apt install -y docker.io docker-compose-v2 nginx certbot python3-certbot-nginx
git clone <ваш репозиторий> /opt/fligel && cd /opt/fligel
cp .env.example .env && nano .env    # SECRET_KEY, PUBLIC_BASE_URL=https://booking.вашдомен.ru, POSTGRES_PASSWORD
docker compose up -d
cp deploy/nginx.conf /etc/nginx/sites-available/fligel   # замените booking.example.ru на свой домен
ln -s /etc/nginx/sites-available/fligel /etc/nginx/sites-enabled/ && nginx -t && systemctl reload nginx
certbot --nginx -d booking.вашдомен.ru
```

**Без Docker:** установите PostgreSQL (`apt install postgresql`), создайте базу и пользователя, положите код в `/opt/fligel`, создайте `.venv` и поставьте зависимости. Затем подключите `deploy/fligel.service` через systemd и nginx так же, как выше.

Миграции базы применяются сами при старте. Резервная копия: `pg_dump fligel > backup.sql`. Поставьте её в cron раз в сутки.

`PUBLIC_BASE_URL` важен: из него строятся ссылки календарей, которые вы вставляете на площадки. Если адрес потом поменяется, ссылки на площадках нужно будет обновить.

## Подключение площадок

Раздел **«Площадки»**. Для каждой площадки выберите уровень:

- **По номерам:** одно объявление на площадке соответствует одному номеру. Так обычно работают квартиры и отдельные объявления на Авито и Суточно.ру.
- **По категориям:** один календарь на категорию номеров. Так Яндекс Путешествия работают с гостиницами. Брони площадки система сама расставляет по свободным номерам категории.

Дальше для каждой строки ссылками нужно обменяться в обе стороны: нашу ссылку скопировать на площадку, а ссылку площадки вставить к нам.

## Финансы: расходы и прочие доходы

Раздел **«Финансы»** с двумя вкладками: **«Расходы»** и **«Прочие доходы»** (завтраки, парковка, трансфер,
доп. услуги, компенсации — всё, что не от проживания). Категории свои у каждого аккаунта: стандартные
(10 для расходов, 6 для доходов) заводятся сами при регистрации, владелец может **добавить свою**,
переименовать, перекрасить или архивировать.

- **Быстрое добавление** — сумма → категория → «Сохранить». В поле «Относится к» выбирается: весь аккаунт
  (общая запись), объект целиком или **конкретный номер**.
- Расходы и доходы **по номерам** учитываются отдельно: на странице есть итог «по номерам», а в отчётах —
  таблица «По номерам» с выручкой, прочими доходами, расходами и **прибылью каждого номера**.
- Общие записи (без объекта) в отчётах делятся между объектами пропорционально числу номеров;
  расходы объекта между номерами не делятся (видны на уровне объекта).
- **Повторяющиеся расходы** (аренда, интернет, зарплата — «каждый месяц N-го числа») создаются сами
  фоновым процессом, тем же, что синхронизирует площадки. День месяца — от 1 до 28.
- Добавлять и править записи может администратор и владелец; удалять и управлять категориями — только владелец.
- Выгрузка в CSV (UTF-8 с BOM — сразу открывается в Excel с русским текстом).

## Отчёты

Раздел **«Отчёты»** — финансовая аналитика за период (этот/прошлый месяц, квартал, год или свои даты),
по одному объекту или сразу по всем.

- **Показатели:** выручка от проживания, прочие доходы, расходы, прибыль, рентабельность, загрузка, средняя цена ночи (ADR),
  доход на номер (RevPAR), средний срок проживания, доля отмен, сколько гости ещё должны доплатить —
  каждый со сравнением к предыдущему периоду и к тому же периоду год назад.
- **Графики** (свой SVG, без сторонних библиотек): доходы/расходы/прибыль по месяцам за год, загрузка
  по дням недели, структура расходов и прочих доходов, расходы по категориям по месяцам (с накоплением).
- **Разбивки:** по объектам, по категориям номеров, по отдельным номерам (таблица с сортировкой — выручка, прочие доходы, расходы и прибыль каждого номера,
  видно, какой номер приносит больше всего, а какой простаивает), по источникам броней и по
  категориям расходов.
- **Комиссии площадок** настраиваются в «Настройках» (% от Авито, Яндекса и т.д.) — отчёт сам
  считает чистую выручку по каждому источнику за вычетом комиссии.
- Выгрузка в CSV.

## Для разработчиков и ИИ-агентов

Этот раздел и `CLAUDE.md` — всё, что нужно, чтобы продолжить работу над проектом.

**Правила (не нарушать)**
1. Каждая бизнес-таблица содержит `account_id`, каждый запрос фильтрует по нему — данные клиентов не смешиваются. Для каждой новой функции есть тест на изоляцию.
2. Защита от двойных броней — `EXCLUDE`-ограничение `bookings_no_overlap` в БД. Не удалять и не обходить; код ловит `psycopg.errors.ExclusionViolation`.
3. 152-ФЗ: никаких внешних CDN, шрифтов, аналитики. Зависимости не добавлять без необходимости (`requirements.txt` минимален).
4. Схему меняют только новыми файлами `app/migrations/0NN_*.sql`; уже применённые не править. Миграции применяются сами при старте.
5. Весь интерфейс и все тексты ошибок — по-русски, понятным языком для владельца гостиницы.
6. Внешние интеграции (Telegram, SMTP, оплата) выключены по умолчанию, включаются через `.env`, в тестах подменяются (`sync.fetch`, `telegram.send_message`, `mail.send`).
7. Секреты и `.env` не коммитить. Перед завершением работы все тесты должны проходить; новая функция — новые тесты.

**Как писать код в этом проекте**
- Эндпоинт — функция `def name(c: Ctx)` с декоратором `@api("manager")` (минимальная роль; `public=True` — без входа), маршрут добавляется в `routes` модуля. Тело запроса — `c.data`, query — `c.q`, параметры пути — `c.path`, аккаунт — `c.account_id`. Ошибка пользователю — `raise ApiError(422, "текст по-русски")`.
- SQL — сырой, через `with tx() as conn:` и `one/all_/run`. Если внутри `with tx()` бросить `ApiError`, транзакция откатится — счётчики и журналы, которые должны сохраниться, пишите до выхода из блока и бросайте ошибку снаружи.
- Фронтенд — один файл `static/admin/app.js`, без сборки. DOM строится через `h(tag, attrs, ...children)`; не передавайте в нативный `append()` массивы или `null` (в странице появится «[object …]») — используйте `h()` или распаковку. Текст из данных вставляйте через `textContent`/`h()`, не через `innerHTML` без экранирования. CSP запрещает внешние ресурсы.
- Деньги — `Decimal`/`numeric`, даты — `date`; «сегодня» берётся по `APP_TIMEZONE`, не по UTC.

**Решения, которые легко принять за ошибки**
- Заявка с сайта сразу занимает номер (статус «Заявка»), снимается через `REQUEST_TTL_HOURS`.
- Фото номеров лежат в БД (`bytea`), SVG не принимаются; публично отдаются только для включённых страниц активных аккаунтов.
- Импорт CSV создаёт подтверждённые брони без уведомлений в Telegram.
- Пробный период и тарифы пока ничего не ограничивают, кроме числа объектов; приостановка аккаунта — вручную через `python -m app.admin`.
- История работы, принятые решения и список «не сделано» ведутся в `PROGRESS.md`.

## Ограничения, которые надо знать

1. **Через iCal передаётся только занятость, цены не передаются.** Цены на Авито и Яндексе меняются в их кабинетах. Автоматическая передача цен есть только через официальное API площадок, а его получают сертифицированные партнёры (RealtyCalendar, TravelLine, Bnovo).
2. **Синхронизация не мгновенная.** Мы забираем календари площадок каждые 15 минут, а площадки забирают наш по своему расписанию. Остаётся короткое окно, когда один номер могут продать дважды. Для этого есть раздел конфликтов.
3. **Авито для гостиниц.** У обычных посуточных объявлений есть синхронизация календаря по iCal. Формат «апарт-отель» на Авито Путешествиях, где все номера на одной странице, судя по описанию Авито, подключается через менеджеры каналов. Проверьте, какой формат у ваших объявлений.
4. **Яндекс для гостиниц:** календарь подключается к категории. После подключения проверьте в Экстранете, как Яндекс считает свободные номера. Если он закрывает всю категорию при первой брони, переключите в «Площадках» способ передачи на «Только даты, когда мест нет».
5. **Онлайн-оплата пока не подключена.** Заявки с сайта приходят со статусом «Ждёт оплаты». Следующий шаг: ЮKassa или CloudPayments с чеками по 54-ФЗ. Механизм удержания номера на время оплаты уже есть в базе (`hold_expires_at`).
