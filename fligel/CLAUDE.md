# Флигель — сервис управления бронированиями (аналог RealtyCalendar)

## Что это
SaaS для посуточной аренды и мини-гостиниц в России. Первый клиент — гостиница на 12 номеров.
Шахматка броней, синхронизация с Авито, Яндекс Путешествиями, Суточно.ру, Островком через iCal,
модуль прямого бронирования на сайте. Система мультитенантная: позже её будут продавать другим клиентам.

## Стек
- Python 3.11+, Starlette + uvicorn, PostgreSQL 14+ (psycopg 3), без ORM, чистый SQL
- Фронтенд — чистый JS без сборки, ES-модули: app/static/admin (админка, по модулю на раздел; общие переменные — объект G в core.js),
  app/static/book (страница для гостей, RU/EN), static/operator (панель оператора), static/guest (анкета и отзыв по ссылке)
- Фоновая синхронизация iCal — поток внутри приложения, очередь в PostgreSQL (SKIP LOCKED), Redis нет
- Подробности в README.md

## Жёсткие правила
1. В каждой бизнес-таблице есть account_id, и каждый запрос фильтрует по нему. Данные клиентов не должны смешиваться.
2. Защита от двойных броней — EXCLUDE-ограничение bookings_no_overlap в БД. Не удалять и не обходить.
3. 152-ФЗ: никаких внешних CDN, Google Fonts, зарубежной аналитики и хостинга. Всё с нашего сервера, данные в РФ.
4. Схему БД не менять в 001_init.sql после первого деплоя на сервер. Только новые файлы migrations/002_*.sql и дальше.
5. Весь интерфейс и все тексты ошибок — на русском, понятным языком для владельца гостиницы.
6. Перед завершением любой задачи прогнать тесты, все должны проходить. Новая функция — новые тесты.
   Тесты: TEST_DATABASE_URL=postgresql://postgres@127.0.0.1/fligel_test python -m unittest discover -s tests -v
7. Не коммитить .env и секреты.
8. Паспортные данные гостей не собираются и не хранятся (152-ФЗ): только имя, телефон, email, пожелания.
9. Мессенджеры — только Telegram и MAX. Все внешние интеграции выключены по умолчанию и в тестах подменяются моками.
10. Новый экран админки — новый модуль static/admin/*.js (не раздувать app.js) + строка в ROUTES + имя файла в SHELL_FILES (sw.js; тест это проверяет).
    Новые таблицы — новой миграцией и с account_id. Перед коммитом JS: eslint --config tests/eslint.config.mjs app/static/admin.

## Известные ограничения (не «баги», а особенности iCal)
- Через iCal передаётся только занятость, цены — нет.
- Яндекс для гостиниц подключает календарь к категории номеров, а не к номеру (это уже поддержано).
- Защита от «эха» (площадка возвращает наши же брони) основана на эвристике в app/sync.py.
